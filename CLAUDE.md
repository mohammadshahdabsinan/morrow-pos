# Xtra Zone Billing - Complete Product Guide

## Overview

**Xtra Zone Billing** is a hybrid POS (Point of Sale) system with two deployment paths:
- **Website** (progressive web app) — live at Cloudflare, browser-based
- **Native Android App** — Capacitor-wrapped, offline-capable, thermal printer support

Both share identical business logic and sync to the same Firebase Firestore backend. The app provides direct thermal printer connectivity via raw TCP sockets (bypasses browser's HTTP layer).

---

## Architecture

### Tech Stack
- **Frontend:** HTML5 + CSS3 + Vanilla JavaScript
- **Mobile:** Capacitor (web-to-native wrapper) + Java for plugin layer
- **Backend:** Firebase Firestore (REST API via client-side credentials)
- **Storage:** localStorage (primary), Firestore (sync target)
- **Printer:** Raw TCP sockets (9100) for ESC/POS thermal printers

### Key Decision: Offline-First + Cloud Sync
- All data stored in **localStorage** for instant access (no server dependency)
- Background sync to Firebase Firestore every 5 seconds
- App works fully offline; syncs when online
- Multiple devices automatically see shared data (same shop ID: `default-shop`)

## Core Features

### 1. **Transaction Management**
- Dashboard: Quick product selection + quantity
- Cart: Add/remove items, apply custom items
- Sale completion: Payment method + status (Paid/Pending/Failed/Wrong Bill)
- **Revenue totals only count "Paid" transactions** (Pending/Failed/Wrong Bill excluded)
- Receipts: Thermal printer print or HTML export

### 2. **Date-Based Transaction Filtering**
- View all-time, today, or any specific date
- Separate stat cards show:
  - All-time totals (all Paid sales)
  - Today's totals (Paid only)
  - Selected-date totals (if date picker used)
- Filters by payment method + transaction status still available

### 3. **Transaction Status Management**
- Each transaction has inline status selector: Paid | Pending | Failed | Wrong Bill
- Status changes reflect immediately in revenue calculations
- Status persists to Firebase on next sync

### 4. **Product Catalog**
- Products organized by categories
- No stock tracking (removed per client request 2026-09-21)
- Search + sort by name/price
- Edit/delete existing products

### 5. **Business Settings**
- Business name, phone, country, locale
- Currency symbol + tax configuration
- Tax mode: exclusive (added on top) or inclusive (calculated from total)
- All settings sync to Firebase

### 6. **Native Printer Support (Android App Only)**
- Requires static IP on thermal printer (WiFi)
- Raw TCP socket to port 9100
- Sends ESC/POS commands directly (no HTTP wrapper)
- Test connection + status feedback
- Printer IP saved to Firebase for multi-device sharing

## Important Constraints & Decisions

### 1. **App Content is Bundled (Offline-First)**
- UI/logic changes (app.js, index.html) require **new APK build** 
- Website updates instantly; app updates only on install/build
- By design: prioritizes offline reliability over instant updates

### 2. **Stock Tracking Removed**
- Was causing UX confusion (default 0 stock made products unsellable)
- Client decision 2026-09-21; no migration needed (field simply ignored)
- Products can be sold without limit

### 3. **Revenue Metrics = Paid Only**
- "Pending", "Failed", "Wrong Bill" transactions never count toward totals
- Reflects actual completed/finalized sales
- Filter UI still shows all statuses, but totals reflect only Paid

### 4. **Printer IP Must Be Static**
- Device power cycles reset DHCP lease → IP changes → app can't find printer
- **Solution:** Set printer to static IP (192.168.1.100 or similar)
- If IP changes, user updates it in app settings once; syncs to all devices via Firebase

### 5. **WiFi-Only Printing**
- Thermal printer must be on same WiFi as app device
- Raw TCP to port 9100 requires direct LAN access
- No internet needed; works fully offline

### 6. **Multi-Device Data Sync**
- All devices targeting same Firebase project + same `SHOP_ID` ("default-shop") see same data
- Transactions created on Phone A appear on Phone B within ~5 seconds
- Settings changes (tax rate, business name) sync the same way

### 7. **No Backend API**
- All business logic runs client-side (Firebase REST API only)
- No server maintenance or uptime SLA
- Tradeoff: Can't do server-side analytics, automated reports, or complex queries

## Making Changes

### Website-Only Change (Settings, Text, Minor Styling)
```
1. Edit app.js or index.html on main
2. git push origin main
3. Cloudflare auto-deploys (live in ~30 seconds)
4. App still has old version (bundled)
```

### App-Impacting Change (Any UI/Logic)
```
1. Edit app.js, index.html, or styles.css on feature/android-app
2. Commit + git push origin feature/android-app
3. Build new APK:
   npm run android:sync
   cd android
   .\gradlew.bat assembleRelease
4. Host APK for download
5. Users install new version manually
6. Cherry-pick safe changes to main for website
```

### Example: Add New Field to Transactions
- **Code change:** app.js (where sale objects are created)
- **Firebase:** Field auto-appears in Firestore on next sync (schema-less)
- **Old devices:** Ignore new field until they update the app
- **Website + app:** Both work; each version handles what it understands

## Debugging & Troubleshooting

### "Revenue totals show 0 but I have sales"
→ Check transaction status. Only "Paid" count. Change pending sales to "Paid" if they're complete.

### "Printer not found" (app)
→ Confirm printer is on same WiFi, IP is static, and set in Business Settings → Printer IP.

### "Different data on phone vs website"
→ Wait 5 seconds for sync to finish. Manually click "Check sync" or refresh browser.

### "Changes on website not showing in app"
→ Website and app are separate builds. Website changes require new APK build to appear in app.

## Critical Notes for Next Session

- Real Firebase credentials in config.js target production data
- Never run automated tests/scripts against prod without user confirmation
- See `feedback_prod_data_safety.md` in memory for incident details (2026-09-21)

- Android/keystore/ holds signing keys (NOT in git, .gitignored)

- No Co-Authored-By lines in commits (user preference saved in memory)

- Capacitor app bundles web content; every UI change needs rebuild
- Website can change independently (Cloudflare auto-deploy)
- This is intentional (offline-first design)
